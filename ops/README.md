# 締め作業 案件管理（MVP）

美容室の閉店後清掃（締め作業代行）の、案件マッチング・スタッフ管理・報酬管理のMVPです。

## 業務の流れ

1. **スタッフ登録**：本部が採用したスタッフを登録し、マイページ（個人用URL）をチャットワークで送る
2. **稼働できる日時の登録**：スタッフがマイページのカレンダーで、月ごとに対応エリア・基本の時間帯・稼働できる日（曜日でまとめて／1日ずつ）を登録。日ごとに時間を変えることもできる
3. **案件の投入**：本部が店舗を登録し、定休日を除いた月の案件を一括作成（スポットで1件追加も可）
4. **シフトの自動作成**：シフト管理の「シフトを自動で組む」で、各案件に、登録した日・エリア・時間帯に合うスタッフから最適な人（店の経験＋今月の件数の少なさ）を入れる。月の上限と同じ夜の重複は守る。入った人にはチャットワークでまとめて知らせる。右パネルから1件ずつ入れることもできる
5. **不可の返答**：スタッフはマイページの「シフト」でカレンダーを見て、都合が悪い日をチェックして理由つきで「不可」を送れる。作業日の7日前まで（`DECLINE_DEADLINE_DAYS`）で、それ以降は本部へ直接連絡。不可の案件は未割当に戻り、本部ホームの要対応に出る（その人には自動で入れ直さない）
6. **全体募集**：自動で入らなかった案件や不可で戻った案件は全体募集にして全スタッフに告知。スタッフは「シフト」の「追加の募集」から希望し、本部が希望者から確定する
7. **リマインド**：前日・当日に担当者へチャットワークでリマインド（本部ホームのボタン、または定時実行。下の「リマインド」参照）
8. **当日の作業と日報**：スタッフはマイページの作業画面で行き方・鍵・注意事項を見て、「清掃を開始する」を押し、終わったらアンケート（選ぶだけ）・作業チェック・写真（画面側で長辺1600pxに縮小）・連絡欄の日報で終了を報告する。報告すると完了になり、本部はシフト管理の右パネルや案件詳細で開始・終了時刻、回答、写真を確認できる。報告がない作業は本部ホームの「完了にしていない作業」から完了にする
9. **サロンオーナーへの通知**：店舗に登録したオーナーのチャットワーク・ルームIDへ、清掃開始と終了（アンケートの回答・連絡・写真の枚数つき）を自動で送る。写真を含む日報は店舗ごとのオーナー用ページ（`/r/<店のトークン>`、ログイン不要）で見られる。URLは店舗詳細の「サロンオーナーへの報告」からコピーできる
10. **報酬**：完了した作業が人ごとの月次報酬に集計される（支払済の記録、CSV出力）。スタッフはマイページの「報酬」で今月の見込みと過去の支払状況を見られる

本部の画面は左メニューの「ホーム」「シフト管理」「スタッフ」「店舗」「報酬」。ホームには今夜の運行（清掃中・未開始）、リマインド送信、要対応（不可が返った案件、全体募集の決定待ち、3日以内の未確定、完了処理待ち、翌月予定の未登録者）が出る。スタッフのマイページは下タブの「ホーム」「シフト」「予定登録」「報酬」。シフト管理では上の3〜6の操作をし、月のシフトを「店舗別カレンダー」（日付×店舗に担当者名、未確定は色分け、日ごとの未確定数）、「スタッフ別カレンダー」（日付×スタッフに確定した店舗と時刻、入れると登録した日、決定待ちの希望）、「一覧」で見られる。セルを押すと右パネルが開き、ページを移らずにシフトへ入れたり希望者から確定したりできる。

### マッチングのルール（`lib/matching.ts`）

案内の対象：稼働中、その月の予定を登録済み、その日が稼働できる日、店舗のエリアが対応エリア内、作業時間がその日の時間帯に収まる、同じ夜の確定案件と移動時間30分込みで重ならない、月の上限件数に達していない、その案件を見送っていない。

確定：本人が希望しているので登録内容は問わず、同じ夜の確定案件との重複と月の上限だけを確認する。並び順のスコアは、その店の経験（1回5点、最大50点）＋今月の確定件数の少なさ（最大30点）。

## 動かし方

Node.js 22.13以上が必要です（組み込みの `node:sqlite` を使用）。

```bash
cd ops
npm install
npm run seed      # 画面確認用のサンプルデータ（任意）
ADMIN_PASSWORD=好きなパスワード npm run dev
```

http://localhost:3000 を開き、`ADMIN_PASSWORD` でログインします。スタッフ画面はスタッフ詳細に出る個人用URLから開きます。

| 環境変数 | 内容 |
|---|---|
| `ADMIN_PASSWORD` | 本部ログインのパスワード（未設定だと `admin`。本番では必ず設定） |
| `APP_URL` | スタッフに送るURLの起点（例 `https://ops.example.com`）。未設定ならアクセス中のホスト |
| `OPS_DB_PATH` | SQLiteファイルの場所（既定 `ops/data/ops.db`） |
| `CHATWORK_API_TOKEN` | 本部のチャットワークアカウントのAPIトークン。未設定なら通知は送らず、画面の文面コピーで手動連絡 |
| `OPS_UPLOAD_DIR` | 完了報告の写真の保存先（既定 `ops/data/uploads`）。写真は本部ログイン中だけ `/photos/…` で見られる |
| `CHATWORK_ADMIN_ROOM_ID` | 本部のチャットワークのルームID（任意）。清掃開始・終了と、スタッフからの不可をここに知らせる |
| `CRON_SECRET` | 定時実行のリマインドAPIを呼ぶための合言葉 |
| `CHATWORK_ALL_STAFF_ROOM_ID` | 全スタッフが入っているグループチャットのルームID（任意）。設定すると全体募集はここに1回だけ告知し、未設定なら全員に個別に送る |

### チャットワークの準備

1. 本部用のチャットワークアカウントで、[APIトークン](https://www.chatwork.com/service/packages/chatwork/subpackages/api/token.php)を発行し `CHATWORK_API_TOKEN` に設定する（ビジネスプラン等ではAPI利用に管理者の許可が必要な場合がある）。
2. 採用したスタッフとコンタクトを結び、ダイレクトチャットを開く。URL末尾 `#!rid412345678` の数字がルームID。
3. スタッフ詳細の「チャットワークのルームID」に入れる（URLをそのまま貼っても数字だけ保存される）。
4. 「チャットワークで本人に送る」で個人用URLを送り、届くことを確認する。
5. サロンオーナーにも同じようにコンタクトを結び、ルームIDを店舗の登録情報「オーナーのチャットワーク」に入れる。

```bash
npm test          # マッチングとDB操作のテスト
npm run typecheck
```

### リマインド

ホスティングの定時実行（cron）から、日本時間で次のように呼ぶ。本部ホームのボタンからも送れる（送信済みの案件には再送しない）。

```bash
# 前日リマインド（毎日18時）／当日リマインド（毎日15時）
curl -X POST -H "Authorization: Bearer $CRON_SECRET" "$APP_URL/api/cron/remind?kind=eve"
curl -X POST -H "Authorization: Bearer $CRON_SECRET" "$APP_URL/api/cron/remind?kind=day"
```

## MVPで割り切っていること（次の候補）

- **ログイン**：本部は共通パスワード1つ、スタッフは推測できない個人用URL。担当者が増えたら本部ユーザーごとのログインにする。
- **通知**：チャットワークへの送信は画面操作と同時に行い、失敗しても再送はしない（画面に失敗人数を表示し、手動送信用の文面を出す）。リマインドの定時実行はホスティング側のcron設定が必要。
- **データベース**：SQLite1ファイル（サーバー1台・定期バックアップ前提）。複数台やサーバーレスで動かすときはPostgresに移す。
- **振込先・インボイス番号**は平文で保存している。本番運用前に暗号化かアクセス制限を入れる。
- 未実装：作業当日のチェックイン・チェックリスト・写真報告、店舗からの評価、キーボックスPINの自動発行、店舗への請求、採用応募の受付。
