# 締め作業 案件管理（MVP）

美容室の閉店後清掃（締め作業代行）の、案件マッチング・スタッフ管理・報酬管理のMVPです。

## できること

| 誰が | 画面 | 内容 |
|---|---|---|
| 本部 | スタッフ | 採用したスタッフを登録し、本人用URLを発行（LINEで送る文面もコピーできる） |
| スタッフ | 入れる日の登録（`/s/<個人用URL>`） | 月ごとに対応エリア・時間帯・上限件数・入れる日（曜日でまとめて／1日ずつ）を登録 |
| 本部 | 店舗 | 契約店舗のエリア・作業開始時刻・定休日・鍵の受け渡し方法・料金・委託報酬を登録 |
| 本部 | 案件 | 定休日を除いた月の案件を一括作成し、「割当案を作って打診」で未割当の案件に1人ずつ打診 |
| 本部 | 案件の詳細 | 候補スタッフをスコア順に表示（対象外の人は理由つき）。複数人に同時打診、取り下げ、上乗せ報酬、完了・中止・担当外し |
| スタッフ | 依頼一覧 | 依頼に「参加する」「辞退する」、またはまとめて参加。最初に参加した人で確定し、住所・鍵・注意事項が表示される |
| 本部 | 報酬 | 月に完了した案件を人ごとに集計、支払済の記録、CSV出力 |

### マッチングのルール（`lib/matching.ts`）

候補になる条件：稼働中、その月の予定を登録済み、その日が「入れる日」、店舗のエリアが対応エリア内、作業時間が登録した時間帯に収まる、同じ夜の別案件と移動時間30分込みで重ならない、月の上限件数に達していない、その案件を辞退していない。

並び順のスコア：その店の経験（1回5点、最大50点）＋今月の件数の少なさ（最大30点）。

運用は「月次シフト＋欠員だけマッチング」（2026-10-26決定）。毎月20日ごろに翌月分を「割当案を作って打診」で一括打診し、辞退・欠員が出た案件だけ案件詳細から個別に打診します。

## 動かし方

Node.js 22.13以上が必要です（組み込みの `node:sqlite` を使用）。

```bash
cd ops
npm install
npm run seed      # 画面確認用のサンプルデータ（任意）
ADMIN_PASSWORD=好きなパスワード npm run dev
```

http://localhost:3000 を開き、`ADMIN_PASSWORD` でログインします。スタッフ画面はスタッフ詳細に出る個人用URLから開きます。

| 環境変数 | 内容 |
|---|---|
| `ADMIN_PASSWORD` | 本部ログインのパスワード（未設定だと `admin`。本番では必ず設定） |
| `APP_URL` | スタッフに送るURLの起点（例 `https://ops.example.com`）。未設定ならアクセス中のホスト |
| `OPS_DB_PATH` | SQLiteファイルの場所（既定 `ops/data/ops.db`） |

```bash
npm test          # マッチングとDB操作のテスト
npm run typecheck
```

## MVPで割り切っていること（次の候補）

- **ログイン**：本部は共通パスワード1つ、スタッフは推測できない個人用URL。担当者が増えたら本部ユーザーごとのログインに、スタッフはLINEログインにする。
- **通知**：打診や確定の通知は自動送信しない。画面の文面コピーを使ってLINEで送る。次はLINE公式アカウントのMessaging APIで自動通知。
- **データベース**：SQLite1ファイル（サーバー1台・定期バックアップ前提）。複数台やサーバーレスで動かすときはPostgresに移す。
- **振込先・インボイス番号**は平文で保存している。本番運用前に暗号化かアクセス制限を入れる。
- 未実装：作業当日のチェックイン・チェックリスト・写真報告、店舗からの評価、キーボックスPINの自動発行、店舗への請求、採用応募の受付。
